# 003 — Give the phone layout a real spacing system

- **Status**: DONE
- **Severity**: HIGH
- **Category**: Responsive spacing / iOS viewport / tokens
- **Estimated scope**: 3 files changed, 2 added, roughly 200 lines

## Problem

The mobile layer was never really built. Reported on iPhone Safari as simultaneously
cramped, wasteful, arrhythmic, and edge-clipped — four symptoms with four distinct causes.

**The floating shell and the content never shared an edge.** `main, footer` padded
`var(--page-gutter)` while the header padded `var(--space-3)`, and two rules hardcoded the
difference:

```css
/* styles.css:208, :220, :482 — before */
.site-header { padding: var(--space-1) var(--space-3); }   /* 12px */
.pill-nav    { max-width: calc(100vw - 24px); }            /* 2 × 12px */
.search-tools{ width: min(calc(100vw - 24px), 760px); }
```

At ≥640px the content moved to a 32px gutter while the header stayed frozen at 12px. The eye
reads two different left edges stacked vertically.

**No safe-area support anywhere.** Zero `env(safe-area-inset-*)` in the repo and no
`viewport-fit=cover`. Three bottom-anchored surfaces sat under the home indicator.

**`100vh` with no `dvh`/`svh`.** On iOS Safari `100vh` is the *large* viewport, so the search
panel and the statute sheet extended below the visible area while the URL bar was showing.

**An off-scale sub-system.** A de-facto 6px half-step in 8 places, 2px/1px gaps, and ad-hoc
paddings (`3px 7px`, `0 9px`, `2px 6px`, `2px 5px`) — the literal source of "inconsistent rhythm".

Only one phone-specific block existed, `@media (max-width: 639px)`, and `--page-gutter` was the
sole token that responded to viewport at all.

## Change

- **One gutter system.** `--gutter-inline` derives from `--page-gutter` and widens to the
  landscape notch; the header, the pill nav, the search panel, and the document column all
  consume it. The magic `calc(100vw - 24px)` / `calc(100vw - 32px)` literals are gone, replaced
  by `--gutter-inline` for document edges and `--overlay-inset` for transient fixed chrome.
- **iOS viewport correctness.** `viewport-fit=cover` on `index.html` only — the six trust pages
  are byte-checksummed in `config/release-governance.json` and need no change, since the default
  `viewport-fit` already insets their layout viewport. Bottom insets on the sheet body, toast,
  update prompt, and footer. `svh` for edge-anchored caps, `dvh` for centred ones, each behind a
  `vh` fallback.
- **Phone rhythm.** Symmetric section padding, tighter heading and legend spacing, and a footer
  that sizes to content instead of a 144px min-height with no padding. `.trust-links` gained a
  row gap — at zero, wrapped 44px targets butted together.
- **Scale hygiene.** Added `--space-05` (2px) and `--space-15` (6px); swept every off-scale
  literal in the stylesheet. `--anchor-offset` replaces three duplicated `scroll-margin-top`
  expressions and adds the `scroll-padding-top` that was missing, so every scroll target clears
  the sticky header rather than only the three that opted in.
- **`--update-prompt-height`** replaces a hand-guessed `96px` toast offset that carried ~16px of
  slop and ignored the safe-area inset the prompt itself now has.

`--header-height` stays 120px, as the brief requires; the vertical space came from section
padding, the footer, and row rhythm instead.

## Verification

`npm test` (132 assertions, unchanged) plus `npm run test:layout` — seven rendered-layout checks
driving the preinstalled Chromium over CDP at 320/375/390/430px. The layout checks are new: the
project previously had no DOM, screenshot, or computed-style coverage, so the design review's
"no horizontal page overflow at 320px" claim was unverified. They caught a real regression during
this work — a `padding` shorthand on `footer` silently reset the inline gutter to zero.

`scripts/cdp.mjs` drives Chromium directly rather than adding a browser-automation dependency:
`compliance/threat-model.md` advertises no runtime dependencies and the SBOM is generated by
enumerating `package-lock.json`, which is empty by design.
